# Contributing

Use the [development setup](docs/setup.md) to run the app with synthetic records.
Keep bug reports and examples free of credentials and real patient information.

Start from the latest `main` and keep the pull request focused on one change.
Describe the behavior it changes and give reviewers the steps to confirm it.
For database changes, verify migrations on a fresh database and a copy with
previous migrations applied.

Run the [development checks](docs/setup.md#development-checks) before opening
the pull request. Include the commands you ran and the results in the PR.
